先确定实现边界，建议把这个功能作为一个新的独立工具页来做，而不是硬塞进现有 Wardrobe 会话体系。

现有 sessions/items/ratings 更偏“评分会话”，适合穿搭/探店打分，不适合“版本号、更新日志、技能树、菜谱结构化内容”这类长期沉淀内容。
页面入口放在新的独立路由下，进入方式沿用现有工具页模式：我的工具 卡片新增入口，同时补充站内搜索索引。
页面顶部直接复用现有 PageHero 方案，下面进入“展开的书”主体区域。
数据层建议做成“菜谱主表 + 结构化扩展字段 + 修订记录”，不要以 Markdown 作为第一编辑源。

原因是你要求“书页原地表单填写”，这更适合 Supabase 结构化存储。
推荐最少包含：基础信息、封面/菜图、版本号、摘要、食材表、步骤表、量化指标、风味雷达数据、标签、熟练度、前置技能、发布状态、排序字段。
更新日志建议独立成修订记录，便于显示版本演进，而不是只存一段文本。
前置技能树如果先求稳，可以先做成“节点 + 依赖关系”的轻量结构；后续再演进成更复杂的技能图谱。
如果以后需要导出成笔记或文章，再从结构化数据生成 Markdown，而不是反过来。
页面信息架构建议按“书的阅读顺序”组织，而不是普通 dashboard。

第 1 个展开页：目录页，列出菜谱分类、最近更新、推荐入口。
后续每一道菜一个 spread：
左页：版本号、更新日志、菜图、基础资料、食材/步骤/参数表、风味雷达。
右页：标签、熟练度、前置技能树、适合场景、失败提醒、生活化备注、搭配建议。
目录、正文、编辑态要共享同一套“书本翻页容器”，避免目录和内容完全是两套 UI。
视觉与组件拆分建议以“书本壳 + 页面内容块 + 功能书签”三层来做。

书本壳：负责展开书脊、左右页、翻页、滚动联动、桌面/移动端布局切换。
页面内容块：负责目录页、左页内容区、右页内容区、雷达图、技能树、更新日志、图片区。
功能书签：单独设计，不跟 CodePen 原组件耦合。书签建议承载目录、添加、编辑、预览、版本记录、发布状态等操作。
这样可以最大化复用书本壳动画，同时让业务内容独立迭代。
CodePen 迁移建议分两步，不要直接把 zip 内容整包塞进页面。

先把 css-sprite-based-flip-carousel-using-scroll-timeline.zip 解包并盘点：HTML 结构、sprite 资源、滚动驱动逻辑、兼容性要求。
再把它改造成项目里的单一书本容器组件，只保留“展开书本 / 翻页 / scroll timeline”相关能力，去掉与业务无关的 demo 结构。
这个仓库里已有不少 CodePen 迁移经验，说明可以走“效果迁移 + 业务重构”的路线，而不是原样嵌入。
书签是额外设计项，建议完全按项目视觉体系单做，不受原 Pen 限制。
“书页原地表单”建议采用“阅读态 / 编辑态切换”的同位编辑，而不是弹窗后台。

点击右上角书签进入编辑态后，当前页内容直接变为输入控件。
左页适合编辑结构化字段：标题、版本、图片、食材表、步骤、量化参数、风味轴。
右页适合编辑标签、熟练度、技能前置、生活化备注。
日志、食材、步骤、技能节点这几类都需要可增删排序的重复表单。
第一版建议使用“显式保存 / 取消”，不要一开始就做自动保存，风险更低。
现有能力可直接复用，减少新依赖。

Hero 直接复用现有 PageHero。
风味雷达优先复用现有 SVG 雷达图思路，仓库里已经有两套雷达实现，不必新增图表库。
技能树优先用 SVG/D3 轻量实现，仓库已有 d3 依赖。
路由切换延续现有独立工具页体验，页面过渡继续跟随当前站内方案。
如果需要后台可配置 Hero 文案，再补站点设置字段；第一阶段也可以先写死文案。
集成点需要一次性规划清楚，避免只做了页面没接入站点。

新增工具入口到 ToolsCard。
同步加入站内搜索内部链接。
如果希望首页或导航更突出，再决定是否加入顶部导航；否则先保持仅在“我的工具”出现。
若编辑仅管理员可用，应沿用现有 admin 权限判定方式；访客只读。
响应式和可用性要单独作为一条设计任务处理。

桌面端保持“完整展开书”。
移动端不建议强行保留双页并排，应改成单页堆叠或伪翻页，否则内容会非常挤。
Scroll-driven 动画要准备降级方案，并考虑 reduced motion。
书签在移动端可能要变成底部或侧边浮动操作条。
推荐的实施顺序如下。

阶段 1：解包并评估 CodePen 书本效果，确认可迁移的动画边界。
阶段 2：定数据模型与 Supabase 表结构，同时明确图片存储路径和权限。
阶段 3：落独立页面骨架，接入 Hero、目录页、书本壳。
阶段 4：先做只读 spread，完成左/右页内容展示。
阶段 5：补书签交互与页内编辑表单。
阶段 6：接入新增、编辑、保存、版本日志、发布状态。
阶段 7：补移动端适配、搜索接入、性能和可访问性收尾。
我的建议结论：
技术路线应选“新建 Recipe 模块 + Supabase 结构化存储 + 复用现有 Hero / Radar / Tool Entry 模式 + 迁移 CodePen 作为书本壳动画”。
不建议复用现有 Wardrobe 会话模型做主干，只能借它的部分表单与评分交互经验。
这样最符合你这次设想：视觉上是一本书，内容上是长期维护的菜谱档案，交互上支持目录、翻页、书签和页内编辑。
